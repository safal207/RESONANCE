# RESONANCE Productization Protocol v0.1

## Goal

Turn repeated verified demand into a reusable product without prematurely converting a one-off client problem into software.

## Heuristic

```text
1 client
→ custom solution / learning engagement

3 similar clients
→ recurring pattern worth formalizing

5+ similar clients
→ productized service candidate

10+ repeating cases with stable acceptance criteria
→ software / API candidate
```

These numbers are a decision heuristic, not a law. Impact, independence of customers, willingness to pay and technical repeatability matter.

## Required evidence

A reusable product hypothesis should be traceable to:

- non-synthetic Problem Cards;
- clear business/operational impact;
- repeated missing capability;
- explicit acceptance conditions;
- pilot evidence where feasible;
- at least one signal of willingness to adopt, test or pay.

## Product ladder

```text
market conversation
→ custom pilot
→ repeated failure pattern
→ protocol / reusable template
→ productized service
→ software / API
→ evidence
→ new publication
```

## Stop conditions

Do **not** productize when:

- the problem appears only once and lacks strategic value;
- each client needs fundamentally different acceptance criteria;
- the workaround is already cheap and adequate;
- the missing capability belongs better in an existing platform/integration;
- demand is inferred only from views, likes, synthetic examples or internal enthusiasm.

## Product traceability

Every reusable product should be able to answer:

1. Which market conversations revealed the problem?
2. Which Problem Cards form the cluster?
3. Which pilots tested the capability?
4. Which invariant/acceptance condition is stable across clients?
5. What evidence shows the product materially improves the workflow?

## North Star

**Verified Product Requests**

Supporting funnel:

```text
Readers
→ Hot-question responses
→ Real workflows
→ Qualified problems
→ Product signals
→ Pilot candidates
→ Paid pilots
→ Repeated patterns
→ Products born
```

## Current status

The protocol exists. It does **not** claim repeated real demand. `market/demand-graph.json` starts with zero real signals and keeps illustrative examples explicitly synthetic.
