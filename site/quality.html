Measure the publication, not just the content.

RESONANCE treats the journal as a verifiable system. Build structure, translations, version history, feeds, browser experience, visual geometry, deployed routes and privacy-aware measurement each have an explicit contract and evidence boundary.

Eight layers

Build → Translation → History → Feed → Browser → Visual → Live → Measurement Each layer answers a different trust question.

Principle

No claim without a boundary. No correction without a trail. No metric without a definition.
RESONANCE Site Health v0.8

1. Publication Contract

The deterministic publication contract builds the journal and checks canonical URLs, structured data, multilingual metadata, sitemap coverage, internal links, Market OS evidence boundaries and other release invariants before deployment.

2. Translation Parity Contract

Managed EN / RU / zh-CN publication groups must preserve sibling routes, locale identity, reciprocal hreflang, visible language switching, action surfaces and evidence-source structure. A green parity check proves structural equivalence, not perfect prose fluency.

3. Corrections + Version History Contract

Registered publications have an append-only temporal identity. Version transitions, change semantics and evidence URLs are checked so a published claim cannot be silently rewritten while still appearing to be the same recorded state.

4. RSS / Subscribe Contract

Multilingual RSS feeds are generated from published HTML rather than a separately maintained article list. Feed ordering, locale routing, RSS autodiscovery and deterministic lastBuildDate are verified before deploy, then the public feeds are fetched again after GitHub Pages succeeds.

5. Experience + UI Geometry Contract

Representative pages are audited with pinned Lighthouse profiles and explicit geometry rules. Performance, accessibility, best practices, SEO, touch-target size, image behavior, overflow and layout stability are release properties rather than informal visual impressions.

6. Multilingual Visual Regression

The homepage, core multilingual articles, Quality, Corrections and Measurement surfaces are captured at phone, tablet and desktop viewports. Horizontal overflow, clipped key content, watched elements outside the viewport and undersized primary controls are blocking defects. Raw pixel-diff percentage remains advisory because legitimate editorial changes also alter screenshots.

7. Live Experience Audit

After GitHub Pages reports success, the public site is measured again. This closes the gap between “the branch built correctly” and “the reader can actually reach the deployed surface.” Live evidence is retained with deploy/run context.

8. Measurement, Privacy & Collector Contract

Site Health v0.8 keeps the v0.7 browser measurement boundary and adds a selected collector architecture without activating production transport:

Article→Meaningful read→Hot question→Workflow intake→Market evidence

The browser runtime has four allowlisted events and a five-field payload. It creates no cookie, local/session storage identity or fingerprint, sends no referrer, user-agent, screen/device fields, email/name, free text or exact client timestamp, and honors Global Privacy Control and Do Not Track. Automated browser audits are suppressed so Site Health cannot manufacture its own readership.

Measurement surfacev0.8 contractWhat it does not prove
meaningful_readVisible ≥ 45 s and scroll depth ≥ 60%Comprehension, agreement or demand.
hot_question_viewHot question ≥ 60% visibleThat the reader considered or answered it.
workflow_intake_openPublic GitHub intake link activatedThat a workflow was submitted.
verified_workflow_openPilot description activated from a market-question surfacePilot qualification or willingness to pay.
CollectorMinimal Cloudflare Worker → Workers Analytics Engine; exact five-field allowlistThat Cloudflare transport metadata does not exist, or that aggregate events represent a person/session.

The selected Worker does not read, hash, persist or export IP, User-Agent, referrer, cookies, geography, visitor IDs or session IDs. Production remains disabled until a deployed endpoint passes live CORS/schema and synthetic-write checks and `RESONANCE_ANALYTICS_ENDPOINT` is explicitly configured.

What the numbers do not prove

A green Site Health gate is controlled evidence, not a universal quality certificate. It does not prove Google ranking, real-user Core Web Vitals, factual completeness, nuanced translation quality, visual taste, reader comprehension, workflow demand, product-market fit or revenue. Those claims require their own evidence.
