Verified Report #023

Reproducible · 12 Aug 2026

The Worker Lost Authority. The Work Was Still Useful.

Worker A lost its lease but completed an immutable result artifact. Auto-publishing the stale result and then adopting it under the current owner produced two effects. Preserving the artifact as data, binding explicit adoption to its digest and both execution epochs, then committing under Worker B's fence preserved one effect.

Core invariant

produce data ≠ publish consequence

#022 proved that authorization can expire while legitimate work is still running. #023 asks whether that expensive work must be discarded. The answer is no — but only if the result is treated as immutable data and a current owner explicitly adopts it before consequence.

Unsafe · stale result auto-publishes

A / fence 1 produces D→A stale auto-publish→effect #1
B / fence 2 adopts same D→publish→effect #2 / CONFLICT

The two effects carried the same artifact digest. The problem was not result identity; it was duplicated consequence authority.

Safe · preserve, adopt, commit

A's result is stored as PRODUCED with digest, producer identity, fence, lease version and production time. Before adoption, the external effect count is zero.

PRODUCED by A/fence 1→B adopts exact digest under fence 2→ADOPTED

B then commits with fencing token 2. Final effect count: 1. A's later attempt with fence 1 receives HTTP 409 / fenced_out.

Digest binding

A one-character digest mutation produced 0 adoption rows. The exact digest produced one adoption row and one committed effect.
